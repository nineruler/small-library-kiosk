# 자이아람터 작은도서관 키오스크

태블릿 + USB 웹캠으로 이용자가 직접 **대출 / 반납**을 하는 Android 키오스크 앱.

- 타깃 기기: 10인치급 태블릿(Lenovo TB128XU), **가로 고정** (`sensorLandscape`)
- `minSdk 30` (Android 11) / `targetSdk 37`

## 화면 흐름

```
홈 ─┬─ 대출하기 → 회원증 스캔 → 책 바코드 연속 스캔 → "다 했어요" → 결과
    └─ 반납하기 ───────────────→ 책 바코드 연속 스캔 → "다 했어요" → 결과
```

- 무입력이 이어지면 자동으로 홈으로 돌아간다(스캔 화면 90초, 결과 화면 20초).
- 회원증이 인식되지 않을 때를 대비해 회원번호 직접 입력 경로가 있다.

## 코라시스 연동 — 현재는 오프라인 기록 방식

코라시스(KOLASYS-NET)는 2023-05-30부터 **관리자 로그인에 2단계 인증이 의무화**되어
(핸드폰·아이핀·이메일 택일, 근거: 개인정보보호법 제29조) 키오스크가 무인으로 접속할 수 없다.
공개 API 도 확인된 범위에서 없다. 정식 경로는 국립중앙도서관 기술정보센터 02-590-0650 문의.

그래서 당분간은 **키오스크가 기록만 남기고 사서가 코라시스에 반영**한다.

- `data/OfflineLibrarySystem.kt` — 검증 없이 찍힌 바코드를 그대로 기록한다.
  장서·회원 목록이 없으므로 제목과 이름은 모르고, 화면은 바코드로 대신 보여준다.
- `data/local/ScanRecordStore.kt` — 날짜별 CSV(`files/records/YYYY-MM-DD.csv`).
  **스캔할 때마다 즉시 append** 하므로 앱이 죽거나 기기가 꺼져도 직전 기록까지 남는다.
  발송은 복사본 전송일 뿐이라 기록을 지우지 않고, 보낸 날짜만 `files/sent/` 에 표식을 남긴다.

### 소장자료 목록 (선택)

코라시스에서 소장자료를 내려받아 **엑셀 파일 그대로** 기기에 넣으면,
책 제목을 보여주고 등록되지 않은 바코드를 걸러낸다.

```
/sdcard/Android/data/com.xiaramteo.kiosk/files/catalog.xlsx   (또는 catalog.csv)
```

```bash
adb push 자이아람터_소장도서.xlsx \
  /sdcard/Android/data/com.xiaramteo.kiosk/files/catalog.xlsx
```

- **.xlsx 를 그대로 읽는다.** "CSV로 저장" 단계가 없으니 인코딩 문제도 생기지 않는다
- 코라시스 엑셀은 **1행이 제목("소장자료 목록"), 2행이 헤더**다. 위쪽 몇 줄을 훑어 헤더를 찾는다
- **열 이름으로** 찾으므로 열 순서가 달라도 되고 쓰지 않는 열이 섞여 있어도 된다.
  등록번호/바코드/자료바코드, 서명/제목/도서명, 저자/지은이, 청구기호 표기를 모두 받는다
- CSV 도 받는다. 한국어 엑셀이 CP949 로 저장해도 읽는다
- 파일을 새로 넣으면 **앱 재시작 없이** 다음 스캔부터 반영된다
- 실제 자이아람터 소장도서(1,777권)로 확인했다. 전부 제목·저자·청구기호까지 읽혔다

**목록 파일이 없으면 검증하지 않고 바코드를 그대로 받는다.** 목록을 넣는 순간 검증이 켜지는
구조라, 목록이 없거나 읽히지 않는다는 이유로 대출이 막히지는 않는다.

### 회원 목록 (선택)

같은 방식으로 `members.csv` 를 넣으면 이용자가 "내 계정이 맞구나" 하고 확인할 수 있고,
등록되지 않은 회원증을 걸러낸다.

```csv
회원번호,회원명
1000000001,구*린
```

> ⚠️ **이름은 내보낼 때 가려서 넣는다**(예: "구*린"). 파일럿 단계의 약속이다.
>
> 로비에 둔 기기라 분실되면 명단이 통째로 나가고, 화면도 뒤에 선 사람에게 보인다.
> 가린 이름으로도 본인 확인에는 충분하고, 사서는 어차피 코라시스에서 회원번호로 찾는다.
> 앱은 파일에 적힌 대로 보여줄 뿐 가공하지 않으므로, **가리는 책임은 내보내는 쪽에 있다.**
>
> 메일로 나가는 대출 기록에는 **회원번호만** 들어간다. 이름은 섞이지 않는다.

`members.xlsx` 또는 `members.csv` 둘 다 받는다. 열 이름은 회원번호/회원바코드/바코드, 회원명/이름/성명.
`docs/members.sample.csv` 참고.

### 남는 한계

목록을 넣어도 **실시간 상태는 알 수 없다.** 이미 대출 중인 책인지, 정지된 회원인지,
연체인지는 코라시스에 물어야 알 수 있고 그 경로가 막혀 있다.
잘못된 기록은 사서가 코라시스에서 걸러야 한다.

#### 목록을 앱에 같이 넣기

`app/src/main/assets/datas/` 에 `catalog.xlsx` 와 `members.csv` 를 두면 설치할 때 함께 들어가고,
앱이 처음 뜰 때 기기 저장소로 꺼내 놓는다(`data/local/BundledData.kt`). adb 를 쓰지 않아도
설치만으로 목록이 들어 있게 하려는 것이다.

**이미 기기에 있는 파일은 덮어쓰지 않는다.** 사서가 새로 내보내 넣은 최신 목록을 앱 업데이트가
예전 것으로 되돌리면 안 되기 때문이다. 번들은 처음 설치했을 때의 출발점이고, 그 뒤로는
기기에 넣은 파일이 늘 이긴다. 번들 목록을 갱신하려면 기기의 파일을 지우거나 새 파일을 밀어 넣는다.

두 파일은 실제 장서·회원 정보라 `app/.gitignore` 로 저장소에서 빼 둔다.
모양은 `docs/catalog.sample.csv`, `docs/members.sample.csv` 를 참고한다.

### 하루 한 번 메일 발송

사서가 매일 받아서 코라시스에 옮겨 적을 수 있도록, 설정한 시각에 그날치 CSV 를 메일로 보낸다.

- `report/DailyReportSender.kt` — **보내지 않은 날짜를 오래된 순으로 모두** 보낸다.
  와이파이가 끊겼거나 기기가 꺼져 거른 날이 있어도 다음 발송에 함께 나간다.
  보낸 뒤에만 표식을 남기므로 실패한 날은 다시 시도한다.
- `report/DailyReportWorker.kt` — WorkManager 주기 작업. 재부팅해도 앱 실행 시 다시 예약한다.
- `settings/MailConfigLoader.kt` — 설정은 화면이 아니라 **기기의 JSON 파일**에서 읽는다.

#### 설정 파일

```
/sdcard/Android/data/com.xiaramteo.kiosk/files/kiosk-mail.json
```

`docs/kiosk-mail.sample.json` 을 참고해 작성한 뒤 넣는다.

```bash
adb push kiosk-mail.json /sdcard/Android/data/com.xiaramteo.kiosk/files/
```

화면에서 입력받지 않는 이유는 두 가지다. 로비에 둔 태블릿에서 긴 메일 주소와 앱 비밀번호
16자리를 손으로 치기 번거롭고, **한글 입력기가 켜져 있으면 영문이 자모로 바뀐다.**
`recipients` 는 배열이라 받는 사람을 여러 명 둘 수 있고, 앱 비밀번호의 띄어쓰기는 알아서 지운다.

**상태 화면**은 홈 화면의 도서관 이름을 **길게 누르면** 열린다(이용자가 실수로 누르지 않도록).
설정이 제대로 읽혔는지, 보내지 않은 기록이 며칠치인지 보여주고 "지금 보내기"로 바로 시험할 수 있다.
아래 **기록** 칸에서는 날짜별 대출·반납 건수와 발송 여부를 보고, 날짜를 누르면 그날 기록을
하나씩 볼 수 있다. 윗줄에 책 제목과 회원명, 아랫줄에 실제로 찍힌 바코드를 둔다 — 사서가
코라시스에 옮겨 적을 때 제목으로 어떤 책인지 알아보고 바코드로 찾기 때문이다. 목록에 없는
바코드면 바코드만 보여준다. **기록 파일 자체에는 바코드만 남는다**(메일로 나가는 내용에
이름이 섞이면 안 되므로). 이름은 화면에서 볼 때만 목록을 뒤져 붙인다.

잘못 찍힌 기록은 줄 오른쪽의 **삭제**로 한 건씩 지운다. 코라시스에 옮겨 적기 전까지 이 파일이
유일한 원본이라 되돌릴 수 없으므로, 무엇을 지우는지 보여주고 한 번 더 묻는다. 그날 마지막
한 건을 지우면 날짜 파일과 발송 표식을 함께 치운다 — 빈 파일을 남기면 "0건"짜리 날짜가
목록에 계속 보이기 때문이다.

설정에 `adminPin` 을 넣어 두면 이 화면에 들어가기 전에 비밀번호를 묻는다(`ui/screen/PinGate.kt`).
비워 두면 묻지 않는다. 숫자 키패드를 직접 그린 이유도 한글 입력기 때문이다 — 시스템 키보드를
쓰면 자모로 바뀌어 숫자가 들어가지 않는다.

> ⚠️ Gmail 은 일반 계정 비밀번호로 SMTP 인증이 되지 않는다.
> 2단계 인증을 켠 뒤 <https://myaccount.google.com/apppasswords> 에서
> **앱 비밀번호 16자리**를 발급받아 `smtp.appPassword` 에 적어야 한다.
>
> 설정 파일에는 앱 비밀번호가 평문으로 들어간다. 앱 전용 저장소라 다른 앱은 읽을 수 없지만,
> **발신 전용 계정**을 쓰고 받은편지함을 비워 두는 것을 전제로 한다. 기기를 잃어버려도
> 그 계정으로 메일을 보낼 수 있을 뿐, 도서관 메일함을 읽히지는 않도록.

## 코라시스 연동 지점

연동 방식이 확정되기 전이라, 도서관 관리 시스템은 인터페이스 하나로만 추상화해 두었다.

- `data/LibrarySystem.kt` — 조회/대출/반납 네 개의 suspend 함수. **여기만 구현하면 된다.**
- `data/MockLibrarySystem.kt` — 지금 쓰는 메모리 기반 가짜 구현(회원 3명, 장서 5권).
- `KioskApplication.librarySystem` — 구현을 갈아끼우는 자리.

화면과 상태 코드는 `LibrarySystem`에만 의존하므로, 실제 연동(REST API / 웹 자동화 / DB)이
어느 쪽으로 가더라도 UI는 손대지 않는다. 실패는 `LibrarySystemException(KioskError)`로 던지면
`ui/Strings.kt`가 이용자용 문구로 옮긴다.

## 바코드 입력 경로 세 가지

바코드는 어느 경로로 들어오든 `onBarcode: (String) -> Unit` 하나로 모인다.

1. **HID 바코드 리더기 (도서 단계는 이것만 사용)** — `scan/HidScannerReader.kt`.
   리더기가 외장 키보드로 잡혀 문자를 빠르게 보내고 Enter 로 끝내는 동작을 모은다.
   `MainActivity.dispatchKeyEvent` 에서 받으므로 어느 화면에서나 스캔된다.
2. **USB 웹캠 (UVC)** — `scan/UvcBarcodeCamera.kt`.
   Lenovo TB128XU 는 커널에 uvcvideo 가 없어 camera2 가 외장 카메라를 노출하지 않는다.
   UVCAndroid(libusb/libuvc)가 usbfs 로 직접 열고, NV21 프레임을 ML Kit 에 넘긴다.
3. **내장 카메라 (CameraX)** — `scan/BarcodeCamera.kt`. 웹캠이 없으면 자동으로 이쪽을 쓴다.
   **회원증 단계에서만** 쓴다. 책 등록 라벨은 막대가 촘촘해 카메라로 해상되지 않아,
   도서 단계는 리더기 전용 안내 화면(`ui/screen/ScannerPanel.kt`)을 띄운다.
   렌즈는 **외장 웹캠 → 전면 → 후면** 순으로 고른다(`scan/CameraSelectors.kt`).
   태블릿을 세워 두면 후면 카메라는 거치대 뒤쪽을 비추게 되므로 전면을 앞세운다.

인식 포맷은 EAN-13/8, CODE-128/39, CODABAR, ITF, QR (`scan/BarcodeDecoder.kt`).

### 실기기 측정 결과 (2026-10-04, Lenovo TB128XU + ABKO APC900 웹캠)

- HID 리더기 경로: 정상. 실물 리더기(TMS HIDKeyBoard)로 회원증·장서 라벨 스캔 확인 완료.
  실제 장서 라벨은 "EM" + 10자리(CODE-128) 형식이다.
  리더기는 HID 인터페이스(class 03)만 노출하므로 영상 미리보기는 제공하지 않는다
- UVC 웹캠 경로: 미리보기와 프레임 수신(1920x1080 MJPEG 30fps)은 정상이나,
  **ABKO APC900 은 고정 초점에 포커스/줌 제어를 노출하지 않아** 책 라벨 바코드를
  해상하지 못한다. 막대 경계가 번져 디코딩 불가. 카메라 교체 없이는 해결되지 않는다.

## 키오스크 모드

- 가로 고정은 매니페스트에서, 화면 꺼짐 방지와 시스템 바 숨김은 `MainActivity`에서 처리한다.
- 화면들은 `ui/screen/Orientation.kt` 의 `AdaptivePane` 으로 **가로·세로 모두 대응**한다.
  거치 방향이 운영 중에 바뀐 적이 있어 한쪽만 되는 레이아웃을 두지 않는다.
- 전용 기기에서 홈 런처로 고정하려면 `AndroidManifest.xml`의 `CATEGORY_HOME` 인텐트 필터를
  주석 해제하고, MDM이나 `startLockTask()`로 화면 고정을 건다.
